# Contributing to DevJob Digest

## Running from source

Requirements: Node.js 18+, and [Claude Code](https://claude.com/claude-code) installed and signed in.

```bash
git clone https://github.com/ka-codes/job-digest-plugin.git
cd job-digest-plugin
npm install
npm start
```

`npm start` launches the Electron app, which runs the existing Express server (`app/server.mjs`) in-process and opens a window pointed at it. To run just the web server without Electron (e.g. for quicker iteration in a browser tab):

```bash
cd app
npm install
node server.mjs
```

then open `http://localhost:4317`.

### Building an installer locally

```bash
npm run dist
```

Produces an unsigned Windows `.exe` (NSIS) or macOS `.dmg` for whichever OS you run it on, via `electron-builder`. Config lives in the root `package.json`'s `build` key.

## Project shape

This ships as two coupled pieces sharing the same data files:

- **A Claude Code plugin** (`.claude-plugin/`, `skills/job-digest/`, `commands/`, `scripts/connectors/`) — a skill that Claude Code runs headlessly to do the actual job search, fit scoring, and document drafting.
- **A local web app** (`app/`) — an Express/Node backend and vanilla HTML/CSS/JS frontend that shells out to the plugin via a headless `claude -p` call (`app/lib/claude.mjs`) and renders the results.
- **An Electron wrapper** (`electron/`) — packages the web app as a desktop application.

## Conventions worth knowing before you send a PR

- **Real `.docx` output is a hard requirement.** Tailored CVs and cover letters are generated by Claude Code's own bundled `docx` skill during a headless run — never a hand-rolled Word-document renderer. Don't add a docx-writing library as a shortcut.
- **Headless prompts must scope narrowly.** Every route that calls `runClaudeHeadless()` (`app/lib/claude.mjs`) builds a prompt that points at an exact file path inside `skills/job-digest/SKILL.md` and explicitly states what to do and what *not* to do. A vague prompt like "use the job-digest skill to do X" reliably causes Claude to run a much broader action than intended (this has caused real bugs — see `app/routes/employers.mjs` and `app/lib/scheduler.mjs` for the pattern to copy).
- **Connectors only get added to `scripts/connectors/employer-boards.json` once verified live.** Don't add an employer's entry speculatively — confirm the board's public API actually returns real postings for that employer first.
- **Data never leaves the user's machine** except to the job board being queried and to Claude Code itself. Don't add telemetry, analytics, or any call to a server you control.

## Adding a new job-board connector

Connectors live in `scripts/connectors/` and share helpers from `scripts/connectors/common.mjs` (`normalizeRole`, `makeId`, `printJSON`, `fail`, `filterBySeniority`, pay-extraction helpers). Look at `scripts/connectors/greenhouse.mjs` or `lever.mjs` for the shortest working examples:

1. Confirm the target platform exposes a public, unauthenticated JSON API for job listings (most ATSs do — Greenhouse, Lever, Ashby, Workable, Workday, and some in-house boards).
2. Write a new script that fetches the listing, maps each posting through `normalizeRole()`, and finishes with `printJSON(filterBySeniority(roles))`.
3. Verify it actually returns real postings for a real employer on that platform.
4. Add the employer to `scripts/connectors/employer-boards.json`, pointing at your new script.

## Reporting issues

Open a GitHub issue. Since this is a local-first tool with no telemetry, please include: your OS, whether you installed via a packaged installer or from source, and the relevant lines from `digest-run-log.txt` or your terminal output if the issue is about a failed run.
